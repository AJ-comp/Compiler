# C11 Core 기준 문법

C 문법의 일부를 수정하고, 수정 전후의 코드가 어떻게 파싱되는지 비교하기 위한 장림 EBNF 기준 문법입니다. **표준 C 전체를 구현한 컴파일러나 전처리기는 아닙니다.** 지원 범위는 아래에 명시합니다.

| 파일 | 역할 |
| --- | --- |
| [`c11-core.ebnf`](c11-core.ebnf) | 저장소에서 관리하는 기준 문법. 첫 규칙이 시작 기호입니다. |
| [`c11-core.cases.json`](c11-core.cases.json) | 문법이 받아들여야 하는 입력과 거부해야 하는 입력의 회귀 예제. |

문법 파일은 장림의 `EbnfGrammarReader`로 읽고, 변환된 문법 객체로 LALR 테이블과 구문 트리를 만듭니다. C 문법을 바꾸려면 기준 EBNF의 사본에서 해당 규칙을 수정하고 기존 예제 및 새 예제를 함께 검사합니다.

## MCP에서 기준 문법 가져오기

MCP 서버는 이 파일을 빌드 시 내장하여 `c11-core`, 버전 `1.0.0`으로 제공합니다. `list_grammars`로 지원 범위와 제한을 확인하고, `get_grammar`에 `grammarId: "c11-core"`를 전달하면 `preset.grammar`에 EBNF 사본을 받습니다. 응답에는 버전과 SHA-256도 포함되어 어떤 기준에서 수정했는지 기록할 수 있습니다. 반환 문법은 LF 줄바꿈을 사용하며 SHA-256은 해당 텍스트의 UTF-8 바이트를 기준으로 합니다.

**서버의 기준 문법은 읽기 전용입니다.** 사용자의 요청은 등록된 원본을 변경하지 않습니다. Claude Code·Codex는 받은 사본을 대화나 사용자 프로젝트에서 수정하고, 수정된 텍스트를 기존 `validate_grammar`, `parse_input`, `run_tests`에 전달합니다. 서버에 사용자별 수정본이나 프로젝트를 영구 저장하지 않으며, 다른 사용자에게 그 수정본을 제공하지 않습니다. 기준 문법의 업데이트는 저장소 변경과 서비스 릴리즈로만 관리합니다.

호출 형식과 연결 방법은 [MCP 사용 가이드](../../docs/MCP.md#내장-기준-문법)를 참고합니다.

## 입력과 지원 범위

기준은 C11입니다. 이 프로필은 구문을 분석하며, 선언된 타입이나 변수의 의미를 판정하지 않습니다. `#include`, `#define`, 조건부 전처리 지시문이 필요한 코드는 외부에서 전처리한 뒤 입력해야 합니다.

| 구문 | 지원 내용 |
| --- | --- |
| 선언과 함수 | 기본 자료형, 저장 클래스, 한정자, 함수 선언·정의, 포인터·배열·함수 선언자, 추상 선언자, 가변 인자 |
| 사용자 자료형 | `struct`, `union`, `enum`, 비트 필드 |
| 초기화 | 집합 초기화, 지정 초기화, 복합 리터럴 |
| 문장 | 블록, `if`/`else`, `switch`/`case`, `for`, `while`, `do`/`while`, 레이블, `goto`, `break`, `continue`, `return` |
| 표현식 | C 연산자 우선순위, 대입·조건·쉼표 연산자, 함수 호출, 멤버·배열 접근, 형변환, `sizeof`, `_Alignof` |
| 리터럴 | 십진·팔진·십육진 정수와 접미사, 십진·십육진 부동소수, 문자열·문자 접두사와 이스케이프, 인접 문자열 |
| 기타 | `_Static_assert`, 줄 주석과 블록 주석 |

`if_header`와 `function_definition` 등 이름이 있는 규칙을 수정 지점으로 사용할 수 있습니다. 중괄호 없는 중첩 `if`도 허용하며, `else`는 구문상 가능한 가장 가까운 `if`에 연결됩니다.

예를 들어 `if_header : 'if' '(' expression ')' ;`에서 `'if'`를 `'unless'`로 바꾸면, 새 문법은 `unless (x) return 1; else return 0;`을 받아들이고 기존 `if` 표기는 거부합니다. 이 수정 전후의 동작과 다른 제어문의 유지도 회귀 테스트로 확인합니다. 이는 구문을 바꾸는 예이며, `unless` 조건을 반대로 실행하는 의미나 실행 코드를 생성하지는 않습니다.

- `//` 줄 주석과 `/* ... */` 블록 주석은 파싱 대상에서 제외합니다. 같은 무시 규칙은 C의 수직 탭(`\v`)과 폼 피드(`\f`) 공백도 처리합니다. 문자열 안의 주석 기호는 문자열 내용으로 유지합니다.
- `NumberLiteral` 토큰 종류는 숫자 정규식을 단어 경계로 감싸지 않고 사용합니다. 따라서 `.5`, `1.`처럼 점으로 시작하거나 끝나는 숫자를 표현할 수 있습니다.
- `StringLiteral`과 `CharLiteral`은 문자열·문자 리터럴용 정규식입니다. `Comment`는 무시할 주석용 정규식입니다. 토큰 종류 지정이 없는 기존 정규식 정의는 `Identifier`로 처리합니다.
- `Reject`는 받아들이면 안 되는 입력을 지정하는 어휘 규칙입니다. 기준 문법의 `invalid_comment` 규칙은 끝까지 닫히지 않은 `/*` 주석을 거부합니다. 이를 `/` 나눗셈과 `*` 역참조 연산자로 잘못 해석하여 파싱 성공으로 처리하는 것을 막습니다. 문자열 안의 `"/*"`는 이 규칙으로 거부하지 않습니다.

직접 문법 객체를 사용하는 경우에도 파싱 전에 EBNF 리더 모듈의 `Reject` 검사를 수행해야 합니다. 기준 문법 테스트와 MCP 어댑터는 이 검사를 거쳐 오류를 반환합니다. `Reject`는 기존 장림 트리 API를 바꾸거나 C의 선언·타입 정보를 판단하는 기능이 아닙니다.

## 제한 사항

- **전처리 미지원:** 헤더 읽기, 매크로 확장, 조건부 포함, 줄 이어 붙이기 등을 수행하지 않습니다.
- **`typedef` 미지원:** `typedef int T;` 선언과 그 이름을 사용하는 `T value;`, `(T)value` 등의 구문은 지원하지 않습니다. 이전 선언과 스코프를 추적하여 이름을 타입 이름으로 분류하는 기능은 별도로 필요합니다.
- **의미 검사 미지원:** 미선언 변수, 타입 적합성, 잘못된 타입 조합, 반환 타입, 레이블 존재 여부, `break`/`continue`가 사용되는 위치 등의 제약을 검사하지 않습니다. 파싱 성공은 C 컴파일 성공을 뜻하지 않습니다.
- **프로필에서 제외한 구문:** `_Atomic`, `_Generic`, `_Alignas`, `_Imaginary`, K&R 방식 함수 정의를 지원하지 않습니다.
- **입력 문자 범위:** 식별자는 ASCII 영문자·숫자·밑줄을 사용합니다. 식별자의 유니코드 문자·범용 문자 이름, 대체 토큰 표기(digraph), 삼중 문자 표기(trigraph)를 지원하지 않습니다.
- **컴파일러 확장 미지원:** GNU, MSVC 등의 전용 확장을 표준 C 구문으로 취급하지 않습니다.

이 문법이 대상으로 삼는 입력은 위 지원 구문으로 작성된 C 번역 단위입니다. 일반 C 프로젝트 전체를 그대로 넣어 헤더·매크로·타입 정보를 해결하는 용도로 사용할 수는 없습니다. 지원 범위 밖의 코드는 별도의 확장과 테스트가 필요합니다.

## 검증

저장소 루트에서 기준 문법 테스트를 실행합니다.

```powershell
dotnet test Tests/Parse.FrontEnd.Parsers.Tests/Parse.FrontEnd.Parsers.Tests.csproj -c Release --filter "FullyQualifiedName~C11CoreGrammarTests"
```

전체 파서 테스트도 같은 프로젝트에서 필터 없이 실행할 수 있습니다. 회귀 예제의 수락·거부 결과 외에, 연산자 우선순위·결합 방향과 중첩 `if`의 `else` 결합은 구문 트리로 확인합니다. 문법의 LALR 충돌 검사도 함께 수행합니다.

원격 서버에서 제공되는 기준 문법과 도구는 배포된 서비스 버전에 따라 결정됩니다. 저장소 변경만으로 운영 서버의 내장 문법이 바뀌지는 않습니다.

## 기준과 저자 맥락

C의 언어 규칙은 [WG14 N1570 C11 위원회 초안의 §6 및 Annex A](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)를 참고했습니다. 문법은 장림에 맞게 구성한 구현이며, 다른 프로젝트의 ANTLR·Bison 문법 파일을 복사하여 가져오지 않았습니다.

장림 엔진의 핵심 구조는 저자가 설계하고 작성한 기존 구현을 사용합니다. 이 디렉터리의 기준 문법과 회귀 예제는 AI 보조로 새로 준비한 별도 자료이며, 기존 엔진에 담긴 저자의 설계·구현과 구분합니다.
