TypeScript 원문에서
구문 트리와 문법 진단을 얻습니다.

TypeScriptGrammar는 JavaScript 문법에 TypeScript의 타입 표기·선언·단언·클래스 확장을 연결합니다. 개발자는 이 클래스가 준비한 문법과 입력 공급자를 기존 LALRParser에 전달합니다.

파싱 결과에는 원문의 타입 노드와 토큰 위치가 함께 남습니다. 이어서 Validate를 호출하면 잘못된 수정자 조합이나 선언 위치 같은 문법 조건을 검사할 수 있습니다. 0.6.0은 아래에 명시한 TypeScript 문법을 지원하며, 전체 문법 지원은 계속 확장 중입니다.

문법을 준비하고, Parsing과 Validate를 호출합니다.

다음 예제의 입력은 타입이 붙은 생성자 매개변수를 사용하는 클래스입니다. public readonly id: number는 TypeScript 문법이며, 클래스의 기본 구조와 생성자 본문은 기존 JavaScript 문법으로 읽습니다.

using System;
using Janglim.FrontEnd.Grammars.TypeScript;
using Janglim.FrontEnd.Parsers.LR;

var language = new TypeScriptGrammar();
var parser = new LALRParser(language.Grammar);
var input = "class User { constructor(public readonly id: number) {} }";

var parsed = parser.Parsing(language.CreateTokenSource(input));
if (!parsed.Success)
{
    Console.WriteLine(parser.FiredException?.Message ?? "파싱 오류");
    return;
}

var diagnostics = language.Validate(parsed.ToParseTree);
foreach (var diagnostic in diagnostics)
    Console.WriteLine($"{diagnostic.Code}: {diagnostic.Message} " +
        $"(위치 {diagnostic.SourceOffset}, 길이 {diagnostic.Length})");

if (diagnostics.Count == 0)
    Console.WriteLine("문법 검사 통과");

Parsing은 원문의 구문 구조를 확인하고 트리를 만듭니다. 그다음 Validate가 완성된 트리에서 선언과 멤버의 문맥을 검사합니다. 따라서 파싱 성공과 진단 0개를 모두 확인해야 문법 검사가 끝납니다.

여기서 number는 트리에 보존되는 타입 표기입니다. 이름이 어떤 타입을 가리키는지, 실제 값이 그 타입에 대입 가능한지를 판단하는 작업은 별도의 타입 검사기가 담당합니다.

입력 종류는 TypeScriptGrammar의 설정으로 선택합니다.

앞의 기본 생성자는 비엄격 모드 Script를 준비합니다. 모듈 파일·표현식 하나·타입 하나를 검사할 때는 같은 생성자의 inputKind를 바꿉니다. 파서를 만들고 Parsing과 Validate를 호출하는 순서는 그대로입니다.

TypeScriptInputKind별 입력 예제
입력 종류선택 코드원문 예제
Script — 기본값new TypeScriptGrammar()let value: number = 1;
Modulenew TypeScriptGrammar(TypeScriptInputKind.Module)export class User { constructor(public id: number) {} }
Expressionnew TypeScriptGrammar(TypeScriptInputKind.Expression)value as number

Script·Expression·Type의 초기 모드는 JavaScriptMode.NonStrict입니다. 엄격 모드로 시작하려면 mode: JavaScriptMode.Strict를 지정합니다. Module은 항상 엄격 모드이며, Script 안에서도 "use strict" 지시문과 클래스의 엄격 모드 조건을 적용합니다.

using Janglim.FrontEnd.Grammars.JavaScript;

var language = new TypeScriptGrammar(
    inputKind: TypeScriptInputKind.Script,
    mode: JavaScriptMode.Strict);

TypeScript API는 JavaScript의 브라우저 호환 옵션을 켜지 않습니다. JavaScript의 HTML 주석 등 Annex B 구문을 검사하려면 JavaScriptGrammar의 웹 호환 설정을 사용합니다.

0.6.0에서는 타입·선언·단언·클래스 확장을 제공합니다.

모듈에서 타입 별칭을 선언하는 export type User = string;은 이미 지원합니다. 위 표의 export type { User };는 기존 이름을 타입으로 내보내는 다른 구문입니다.

TypeScript 계층은 기존 JavaScript 문법과 검사기를 재사용합니다.

TypeScriptDialect가 JavaScript 문법에 타입·선언·클래스 규칙을 연결하고, TypeScript의 렉싱 정책이 타입 괄호와 실행 표현식의 연산자를 구분합니다. 공통 파서는 준비된 문법과 입력 공급자로 원문을 읽습니다.

정적 검사에서는 TypeScript 전용 조건을 확인한 뒤, JavaScript 검사에 필요한 별도 트리 뷰를 만듭니다. 이 뷰에서 타입 표기를 제외하고 기존 JavaScript 검사를 수행하므로 함수·선언·클래스의 공통 조건을 재사용할 수 있습니다. 개발자가 받은 원본 트리에는 타입 노드와 원문 위치가 그대로 보존됩니다.

검증 기준과 저자 맥락

이번 TypeScript 지원은 고정한 TypeScript 7.0.2 참조 구현과 비교하며 개발했습니다. 참조 커밋과 비교 도구는 TypeScript 검증 도구 안내에 기록되어 있습니다. 2026-10-28 검증에서는 현재 구현 범위의 TypeScript 테스트 975개가 통과했습니다. 전체 TypeScript 문법의 완성 여부는 남은 구문 구현과 별도의 전체 대조로 확인합니다.

Janglim의 핵심 LR 구조는 저자가 설계하고 작성했습니다. 이번 TypeScript 문법·렉싱 정책·정적 검사·테스트와 문서는 저자의 기존 엔진과 JavaScript 지원 계층 위에 대화에서 합의한 범위를 AI 보조로 추가했습니다.
